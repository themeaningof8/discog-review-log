# フルスタック段階導入ロードマップ（設計）

**作成日:** 2026-05-05  
**ステータス:** 草案（レビュー待ち）

## 1. 概要

本ドキュメントは、**Astro（Vite 内蔵）+ SolidJS + Tailwind v4** をフロントに、**Elysia on Bun** を API に置く構成へ移行しつつ、**理解度の向上**を最優先目的の一つとして **小さな縦割り（機能を少しずつ足す）** で進めるためのロードマップである。

既存リポジトリのハーネス（Biome / TypeScript strict / Vitest 等）は維持しつつ、**パッケージマネージャとランタイムを Bun 第一へ寄せる**方針で、`README`・`docs/harness-decisions.md`・`docs/tech-stack.md` の更新は該当フェーズで追従する。

## 2. 目的と非目的

### 2.1 一次目的

- **学習:** 各フェーズで「新しく触る概念」を 1〜2 個に抑え、噛み砕いて理解する。
- **成果物:** 公開 URL で **読み取りは誰でも**、**書き込みは運用者のみ** から始められるアプリの骨格。
- **コスト:** デプロイ候補の比較では **コスト（無料枠・従量）を最優先軸** とする。

### 2.2 MVP での非目標

- 一般向けの複雑な認可モデル、ソーシャルログイン必須。
- 高トラフィック向けのスケール設計（数十〜数百ユーザー想定は **後続**）。
- Nitro と Elysia の統合など、検証コストが高い構成。

## 3. 合意済みの制約

| 項目 | 合意内容 |
|------|----------|
| ツールチェーン | リポジトリ全体を **Bun 第一**（`bun install` / `bun.lockb` を前提。既存の pnpm 固定から移行する） |
| フロント | **Vite を前提とした Astro**（ハーネス上の「Vite を避ける」方針は **本スペックで意図的に更新**） |
| バックエンド | **Elysia on Bun**（Drizzle・Better Auth 等はフェーズで導入） |
| 公開 | **公開 URL が欲しい**。読み取りは公開でよい |
| 書き込み | **最初は運用者本人のみ**（後からユーザーを足せる余地を残す） |
| デプロイ | **詳細は未調査**。調査はロードマップ上の専用フェーズで実施 |
| 規模 | MVP は **自分 + ごく少数** |

## 4. システム境界（目標像）

- **`web`:** Astro + Solid（Islands）+ Tailwind v4。ビルドは Astro が利用する Vite。
- **`api`:** Bun 上の Elysia。ローカルでは `Request` を直接渡すテスト（`bun:test`）から始める。
- **境界:** HTTP(S)。開発時は同一オリジンに寄せるための **リバースプロキシまたは Astro 側 dev proxy** を検討（詳細は実装計画で確定）。

## 5. 学習の進め方（全フェーズ共通）

各フェーズには以下を必ず書く（実装計画テンプレでも再利用する）。

1. **このフェーズで学ぶこと**（1〜2 テーマに限定）
2. **完了の定義**（動作確認手順を具体的に）
3. **次フェーズに進む条件**（完了定義を満たすこと）
4. **意図的にやらないこと**（スコープずれ防止）

## 6. ロードマップ（細分化）

フェーズ番号は依存関係が軽い順。並列可能なものはメモに記載。

---

### フェーズ 0 — 方針の確定とドキュメント整合

- **学ぶこと:** 変更がハーネス文書に与える影響の整理。
- **成果物:** 本ドキュメントの承認。必要なら `docs/harness-decisions.md` / `docs/tech-stack.md` に「Bun 第一・Astro/Vite 採用」の旨を追記する **タスクの明記**（実編集はフェーズ 1 でも可）。
- **完了の定義:** ロードマップに異論がなく、次フェーズの優先順位に合意。
- **やらないこと:** アプリコードの追加。

---

### フェーズ 1 — Bun ワークスペースの骨格

- **学ぶこと:** `package.json` workspaces、`bun` のスクリプト実行。
- **成果物:** ルートで `bun install` が通る。`apps/web` と `apps/api`（名前はこのままでも可）の空パッケージ。ルートから各パッケージの placeholder スクリプトが呼べる。
- **完了の定義:** CI を壊さない方針が決まっている（段階的に Bun へ寄せるか、並行期間を設けるか）。
- **やらないこと:** フレームワーク本体の導入。

**並列可:** フェーズ 0 の文書マージと並行検討。

---

### フェーズ 2 — API 最小（Elysia の「1 本」）

- **学ぶこと:** Elysia のルート定義、`bun:test` でハンドラを直接叩く。
- **成果物:** `GET /health`（または `/api/health`）が 200 を返す。テストが通る。
- **完了の定義:** サーバプロセスを立てずにテストで網羅。
- **やらないこと:** DB、認証、OpenAPI。

---

### フェーズ 3 — フロント最小（Astro + Solid の 1 Island）

- **学ぶこと:** Astro のプロジェクト構造、Solid Island のマウント。
- **成果物:** トップページに Solid の小さなインタラクション（例: カウンター）を 1 つ。
- **完了の定義:** `bun run dev`（またはワークスペース経由）で表示できる。
- **やらないこと:** Tailwind、本番デプロイ。

---

### フェーズ 4 — Tailwind v4 の導入

- **学ぶこと:** `@theme` など CSS-first 設定の考え方（プロジェクト既定に合わせる）。
- **成果物:** フェーズ 3 の UI に最低限のスタイルが付く。
- **完了の定義:** ビルドが通り、主要クラスが当たる。
- **やらないこと:** デザインシステム全体。

---

### フェーズ 5 — ローカルでの front ↔ api 結線

- **学ぶこと:** 開発時プロキシ、または CORS と cookie の基礎。
- **成果物:** ブラウザから API の `/health` を叩いて結果を画面に出せる。
- **完了の定義:** ローカルでのエンドツーエンド手順が README レベルで説明できる。
- **やらないこと:** Eden Treaty、本番 TLS。

---

### フェーズ 6 — デプロイ調査スパイク（フロントのみ）

- **学ぶこと:** 無料〜低コスト帯の静的ホスティングの違い（2026 時点の公式ドキュメントに依拠）。
- **成果物:** **調査メモ**（比較軸: 無料枠、カスタムドメイン、ビルド制限、環境変数）。候補 2〜3 の短い表。
- **完了の定義:** 「どこに静的 `dist` を載せるか」の一次決定または「決めない理由」。
- **やらないこと:** API のデプロイ。

---

### フェーズ 7 — フロントの本番デプロイ（読み取り公開）

- **学ぶこと:** 選んだホスティングのデプロイパイプライン。
- **成果物:** 公開 URL でトップページが見える（フェーズ 3〜4 の内容）。
- **完了の定義:** 再現手順（最小）がドキュメント化されている。
- **やらないこと:** 書き込み API の公開。

---

### フェーズ 8 — API デプロイ調査スパイク（Bun 実行環境）

- **学ぶこと:** Bun がコンテナ/PaaS で動かすときの要件（ベンダー公式情報）。
- **成果物:** 候補比較表（コスト最優先）。**アプローチ A（静的 CDN + 別ホスト API）** を第一候補、**単一 VPS 同居** を第二候補として評価。Workers ネイティブだけで Bun を捨てる案は **代替・警告付き** で記載。
- **完了の定義:** 一次候補が決まる。
- **やらないこと:** マルチリージョン。

---

### フェーズ 9 — API の本番デプロイ（読み取り専用または無害なエンドポイントのみ）

- **学ぶこと:** シークレットの注入、ログの見方。
- **成果物:** 公開 URL 上で `/health` が叩ける。
- **完了の定義:** 監視の最小（失敗時に気づく手段）がメモされている。
- **やらないこと:** 本番 DB。

---

### フェーズ 10 — データ層（Drizzle + SQLite）ローカル

- **学ぶこと:** Drizzle のスキーマとマイグレーションの流れ（Bun + SQLite の組み合わせ）。
- **成果物:** ローカルで「レビュー 1 件」の作成・取得ができる。
- **完了の定義:** テストで担保。
- **やらないこと:** 本番 DB の選定確定。

---

### フェーズ 11 — 本番 DB とマイグレーション方針

- **学ぶこと:** 選んだホストでのファイル永続化の限界、またはリモート DB のコスト。
- **成果物:** 本番で動く読み取り API（公開）。
- **完了の定義:** フェーズ 7 のフロントから本番 API のデータを読める。
- **やらないこと:** 一般ユーザー登録。

---

### フェーズ 12 — 書き込み経路の保護（運用者のみ）

- **学ぶこと:** 共有シークレット、Basic 認証、または管理用トークンのトレードオフ。
- **成果物:** 公開読み取りは維持しつつ、作成・更新・削除は認証付き。
- **完了の定義:** シークレットがリポジトリに入っていない。
- **やらないこと:** Better Auth のフル導入（次フェーズ以降のオプションとして文書化）。

---

### フェーズ 13 — OpenAPI / Eden Treaty（任意）

- **学ぶこと:** 型安全なクライアント生成の価値とコスト。
- **成果物:** 最小 1 エンドポイントで型がクライアントに伝わる。
- **完了の定義:** リファクタで型が壊れたときにコンパイルが赤くなる。
- **やらないこと:** 全エンドポイントの一括移行。

---

### フェーズ 14 — Better Auth など本格的認証（任意・後続）

- **学ぶこと:** セッション、OAuth、CSR F の基本。
- **成果物:** フェーズ 12 の簡易保護からの移行計画のみでも可。
- **完了の定義:** 「なぜ今そのレベルか」をドキュメント化。
- **やらないこと:** 不必要なプロバイダ列挙。

---

### フェーズ 15 — WebSocket / リアルタイム（任意）

- **学ぶこと:** Elysia `.ws()` とデプロイ先の制約。
- **成果物:** ローカルで購読が動くプロトタイプ。
- **完了の定義:** 本番で必要になった時点の調査メモに留めるのも可。

---

## 7. リスクと緩和

| リスク | 緩和 |
|--------|------|
| Bun 移行で既存 CI/hooks と衝突 | フェーズ 1 で並行期間またはジョブ分割を明示 |
| 無料枠の変動 | フェーズ 6・8 は「日付つきの調査メモ」を成果物に含める |
| 学習目的と納期の両立 | 各フェーズの「やらないこと」を守る |
| Workers と Bun の混同 | API は **Bun が動く環境**に限定し、例外は文書化 |
